# Искра: первый прототип Rive

Это отдельная визуальная лаборатория одного робота. Она устанавливается рядом с
Clicker под идентификатором `com.mycompany.clicker_rive_lab` и не открывает сохранение,
инвентарь, прогрессию или аккаунт игры. Основной код игры, APK 16 и AAB 17 сохранены.
Переключение всей коллекции на Rive пока не включено.

## Запуск

На Android установи `build/rive-prototype-v1/clicker-rive-lab-arm64.apk`.
Это release-сборка лаборатории с тестовой подписью для устройств ARM64.
Внутри нет рекламных показов или выдачи игровых наград.

На компьютере из `C:\Clicker`:

```cmd
run_rive_prototype.cmd
```

Команда запускает Flutter-прототип в Chrome в режиме profile. Для отдельного
нативного Windows EXE нужен компонент Visual Studio «Desktop development with C++»;
он в текущем окружении не установлен. Проверки нативных контролов выполнены
в настоящем тестовом движке Flutter для Windows.

Кнопки переключают восемь состояний: idle, move, attack, defend, charge, hit,
victory и defeat. Переключатель «Арена» показывает второй экземпляр Искры.
Снаряд летит одну секунду между роботами, затем запускаются реакция на попадание,
искры и короткое сотрясение камеры. Это демонстрация анимаций; результаты боёв
и награды основной игры определяет существующий Python-код.

Осмотр: двойное нажатие или значок лупы, колесо мыши / щипок для масштаба,
перетаскивание для смещения. Во время осмотра робот останавливается; дыхание и
мимика продолжаются. Кнопка рядом с лупой сбрасывает камеру. Доступен режим
«Меньше движения». Переключатель FPS показывает частоту кадров, UI p95 и Raster p95
на платформах, где Flutter предоставляет FrameTiming.

## Что изменено в архитектуре

Существующий `src/robot_motion.py` собирает актёра из 19 контролов Flet и SVG.
`GameSession._ticker()` раз в секунду обновляет позы, а Flutter интерполирует
преобразования между обновлениями. Эта реализация продолжает обслуживать игру.

В прототипе Python отправляет семантическую команду одному `RobotRive`, а
анимация выполняется в клиенте Flutter / Rive без Python-цикла на каждый кадр.
Используются Flet 1.0.4, Python flet-rive 1.0.4, Rive Flutter 0.14.11 и локальное
дополнение к MIT-расширению flet-rive из дерева Flet v1.0.4. Стандартный Rive-контрол
сохранён; новый `RobotRive` добавляет управление данными и сценой.

- RML содержит отдельные голову, корпус, плечи, предплечья, кисти, колёса,
  звенья гусеницы, глаза, брови и три выражения рта.
- Машина `RobotMotion` управляет восемью состояниями через современный view model.
  Удар имеет замах, выброс, отдачу и возврат. Попадание и поражение имеют свои позы.
- Движение вычисляется по прошедшим секундам. Углы колёс равны расстоянию / радиусу;
  звенья проходят замкнутую траекторию с той же линейной скоростью.
- Самостоятельный патруль, развороты и возврат после одноразовых анимаций проверены
  при 30, 60, 120 Гц и неравномерных интервалах.
- Эффекты ограничены пулом из 40 частиц. Камера и эффекты перерисовываются в клиенте.
  Тикер останавливается при приостановке приложения; возврат сбрасывает его часы.
- Локальное расширение используется только проектом `prototypes/rive_robot`.
  Корневые зависимости и игровая модель данных не изменены.

Для следующего подключения к игре подготовлен адаптер `visual_action()`:
guard → defend, special → attack, feed → charge. Событие атаки передаётся с новым
`command_id`; повторная доставка того же события игнорируется. Расчёт хода,
энергия, золото, корм и сохранение остаются ответственностью GameSession.

## Проверки и производительность

Исходные 186 Python-тестов прошли. Добавлено 17 тестов Flutter: независимость
движения от частоты кадров, развороты, гусеницы, восстановление, эффекты,
реальная загрузка .riv, адаптер Flet, смена источника, камера, освобождение
ресурсов и пять размеров сцены от 320×640 до 1280×720.

Для сравнения до/после используется один движок Flutter Windows и 600 кадров
на вариант. Старая сцена получает обновления раз в секунду с сохранением
идентификаторов контролов; обновляется существующее дерево Flet. Прототип
анимируется непрерывно. Rive загружается настоящей библиотекой C++, рендерер
в этом тесте — Factory.flutter. Подключена официальная release DLL Rive,
поскольку отладочная DLL требует отсутствующие компоненты Visual Studio.

| CPU / layout одного pump | Существующий актёр | Прототип Rive |
|---|---:|---:|
| Медиана | 0,836 мс | 0,853 мс |
| p95 | 1,849 мс | 1,177 мс |
| Максимум | 46,884 мс | 5,523 мс |
| Более 16,67 мс из 600 | 7 | 0 |

Это измерение тестового движка вне экрана, а не доказательство частоты 60 FPS
на физическом дисплее. Исходные сцены отличаются детализацией; новые анимации
работают на каждом кадре. Дополнительно CLI Rive проверяет 600 кадров и
последовательности из восьми снимков для каждого состояния. Полные числовые
результаты находятся в `build/rive-prototype-v1/verification.json`.

Дополнительный прогон выполнен в настоящем Chrome без окна, Flutter profile,
Rive Renderer (Factory.rive), размер 2382×1648. Два экземпляра робота циклически
переключали attack, charge, defend, hit, victory и idle; в тесте попадания пул
заполнялся до 40 частиц. После прогрева собраны 20 окон FrameTiming: медиана
119,996 кадра/с, минимум 119,972; максимальные p95 — UI 4,401 мс и Raster 1,600 мс.
Ошибок Flutter не зарегистрировано. Отдельный прогон двух роботов в покое дал
медиану 96,271 кадра/с; результаты зависят от прогрева и фоновой нагрузки.
Это результаты движка в тестовом браузере, а не измерение частоты физического
монитора, нативного Windows EXE или телефона.

Для Python также измерена сборка полной структуры контрола и сериализация в JSON:
медиана 0,841 мс → 0,028 мс; 19 контролов → 1. Это не размер сетевого diff
и не частота кадров клиента.

60 FPS остаются целью для поддерживаемых устройств. Проверка телефона отложена
по запросу пользователя. Для неё в APK есть индикатор FPS: после прогрева нужно
проверить патруль, осмотр, арену и быстрые смены состояний в обеих ориентациях.
При 60 Гц бюджет кадра — примерно 16,67 мс. Массовый переход роботов следует
проводить после проверки реального устройства и окончательного вида Искры.

## Редактирование и повторная сборка

Редактируемый источник: `animation/rive/spark/scene.rml`; генератор:
`animation/rive/generate_spark.py`. В файле нет скриптов. CLI установлен по
официальной инструкции, версия 1.9.2; вход выполнен через `rive login`.
Экспорт на текущем плане Rive содержит фирменную заставку. Экспортированный
бинарный файл сохраняется без изменений и проверяется побайтово внутри APK.

```cmd
uv run python animation\rive\generate_spark.py
uv run python tools\prepare_rive_prototype.py
uv run python tools\verify_rive_prototype.py
```

`prepare_rive_prototype.py` выполняет официальный `--publish` в локальный файл,
проверяет RML и копирует .riv в ресурсы лаборатории. Публичную страницу Rive
или релиз игры эта команда не создаёт.

Нативные проверки в PowerShell:

```powershell
cd C:\Clicker\prototypes\rive_robot\flutter
& "$env:USERPROFILE\flutter\3.44.8\bin\dart.bat" run rive_native:setup --platform windows
$env:PATH="$PWD\build\rive_native\native\build\windows\bin\lib\release;$env:PATH"
& "$env:USERPROFILE\flutter\3.44.8\bin\flutter.bat" test --concurrency=1
```

Android:

```powershell
& "$env:USERPROFILE\flutter\3.44.8\bin\flutter.bat" build apk --release --target-platform android-arm64
cd C:\Clicker
uv run python tools\package_rive_prototype.py
```

Версии Android-сборки закреплены на проверенной связке проекта: Gradle 8.14,
AGP 8.11.1, Kotlin 2.2.20, Java 17. Сборку и Flutter-тесты следует запускать
последовательно, потому что они используют общие генерируемые файлы плагинов.

Профилирование Chrome можно повторить двумя терминалами: запустить
`uv run python tools\collect_rive_profile.py --scene combat` из корня проекта,
затем из `prototypes\rive_robot\flutter` выполнить:

```powershell
& "$env:USERPROFILE\flutter\3.44.8\bin\flutter.bat" run -d chrome --profile --web-run-headless --web-hostname=127.0.0.1 --dart-define=RIVE_START_FPS=true --dart-define=RIVE_LOG_FPS=true --dart-define=RIVE_START_ARENA=true --dart-define=RIVE_PROFILE_COMBAT=true --dart-define=RIVE_METRICS_URL=http://127.0.0.1:8833/metrics
```

После получения отчёта нажми `q` в терминале Flutter. Метрики отправляются
только локальному коллектору. Обычные сборки не содержат адреса коллектора и
не включают автоматический цикл боя.
