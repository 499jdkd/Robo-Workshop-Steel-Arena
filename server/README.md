# Сетевая арена Robo Workshop

FastAPI: PostgreSQL для бесплатного облачного размещения; SQLite/WAL для локального запуска. Игроки, результаты,
друзья, рейтинги и кланы хранятся на сервере. Боты никогда не попадают в PvP.
Офлайн-прогресс клиента не считается доверенным источником сетевых характеристик.

## Локальный запуск

Из корня проекта:

```powershell
uv pip install --python .venv/Scripts/python.exe -r server/requirements.txt
$env:CLICKER_ARENA_DB = 'C:\Clicker\.cache\arena-local\arena.sqlite3'
uv run uvicorn server.app:app --host 127.0.0.1 --port 8000 --workers 1
```

Перед запуском основной игры:

```powershell
$env:CLICKER_ARENA_URL = 'http://127.0.0.1:8000'
uv run python src/main.py
```

Обычный игрок не вводит URL. Для выпуска адрес HTTPS записывается разработчиком
в `src/assets/config/network.json` (`arena_url`), после чего собирается приложение.
Если адрес не задан, экран сообщает, что сервер не подключён. Локальные
тренировки с обозначенными ботами продолжают работать. Сервис старого
рейтинга касаний MongoDB имеет другой протокол и не подходит вместо этого API.

Смена сервера использует отдельную приватную сетевую личность. Bearer-токен
хранится в пользовательском каталоге; на сервере — только SHA-256 токена.
Файлы `arena-identity-*.json`, база, резервные копии и ключи не публикуются в Git.

## Правила и API

`GET /health`: `protocol: 1`, `rules_version: 3`, `opponents: human-only`.
Это проверка процесса без запроса к базе: она не расходует compute Neon в простое.
`GET /ready` проверяет подключение к базе; при недоступности возвращает 503.
Расчёт контрприёмов общий с основной игрой (`src/combat_rules.py`). Поддерживаются
32 конструкции и 20 видов оружия. Сервер задаёт ограниченные бюджеты здоровья,
урона и защиты по классу; уровни, звёзды и бонусы платных предметов не повышают их.
Расчётная сила — из серверного каталога, а не число, присланное клиентом.

Подбор учитывает режим, рейтинг (разница до 400) и силу сборки (до 100).
Рейтинговый режим: победа +16 рейтинга, 25 жетонов; поражение −16, 5 жетонов.
Сбалансированная практика и дружеская дуэль не начисляют рейтинг и награды.
Сервер проверяет владельца хода, энергию, перезарядку, уникальный ID команды и
ревизию. Повтор запроса возвращает прежний результат. Тайм-аут хода — 45 секунд;
отключившийся игрок проигрывает один раз. Лимит боя — 120 ходов, затем сравнение
доли оставшегося здоровья; при равенстве ничья без наград.

- `POST /register`, `GET /me`, `GET /ranking`, `GET /history`.
- `POST/DELETE /queue`, `GET /match/current`, `POST /match/{id}/turn`.
- `GET /friends`, `POST /friends/action`: request/accept/remove. Запрос принимает
  только адресат. Код друга — ID его сетевого профиля на вкладке друзей.
- `POST /duels`, `POST /duels/join`: одноразовый код из 8 символов, срок 10 минут.
- `GET /clans?search=...`, `POST /clans/action`: create/join/leave/donate/mission,
  edit/promote/demote/kick/war/war_claim. Описание и эмблему меняет глава; офицера
  назначает глава. Выход главы передаёт владение следующему участнику.
- Клановые задания и войны считают только подтверждённые рейтинговые победы.
  Для недельной награды нужны 20 общих и хотя бы одна личная победа. Получение
  награды защищено уникальной записью в БД.

Схема API: `/docs`. Перед миграцией старой базы создаётся SQLite backup с учётом
WAL: `*.before-social-v2.backup`. Идентификаторы и токены сохраняются.

## Проверки

```powershell
uv run python -m unittest discover -s tests -p test_social_arena.py -v
uv run python -m unittest discover -s tests -p test_online_http.py -v
uv run python tools/smoke_online_server.py
```

Последняя команда запускает настоящий loopback HTTP-сервер и два независимых
клиента `OnlineArena` основной игры с временными профилями. Они принимают запрос
дружбы, находят друг друга, завершают бой и сравнивают состояние после каждого
хода. Локальные сохранения пользователя не читаются и не изменяются. Проверка
2026-11-15 завершила матч за 14 ходов; отчёт —
`.cache/rework-review/two-client-http.json`. Это локальная сетевая проверка,
а не доказательство доступности публичного сервера или проверки двух телефонов.

## Публичное развёртывание без оплаты

Пошаговая настройка: [DEPLOYMENT.md](../DEPLOYMENT.md).
`render.yaml` создаёт **Render Free**, без диска и платной базы. В Render задаётся
секрет **CLICKER_ARENA_DATABASE_URL** со строкой подключения **Neon Free**.
Переменная имеет приоритет над локальным `CLICKER_ARENA_DB`. При запуске в Render
отсутствующий секрет возвращает 503: сервер не создаёт временный SQLite-рейтинг.

`server/Dockerfile` слушает `$PORT` одним worker. Контекст Docker содержит только
сервер и три общих модуля правил, без игры, сохранений или ключей. SQL-параметры
передаются отдельно от запросов. PostgreSQL использует транзакционную advisory
блокировку для подбора, ревизий хода и наград; она освобождается при commit/rollback,
поэтому совместима с transaction pooling Neon. Соединения закрываются после
запросов. Время хранится в DOUBLE PRECISION, без округления дедлайнов до минут.

SQLite сохраняется для локальной разработки. Не использовать его на временном
диске Render Free и не запускать реплики с независимыми файлами. Смена внешней
базы не меняет офлайн-прогресс игры. Это первое публичное развёртывание сетевой
арены, поэтому внешняя база изначально пустая.

Render Free засыпает при простое; у Neon Free ограничена месячная compute-квота.
Актуальные ограничения и ссылки — в DEPLOYMENT.md. Для масштабного запуска
остаются восстановление сетевого аккаунта, ограничение частоты запросов на шлюзе,
мониторинг, резервирование и нагрузочное тестирование. Публичный PvP не объявляется
готовым до матча двух клиентов через внешнюю сеть. Клановые войны также требуют
этой проверки.
