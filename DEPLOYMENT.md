# Бесплатное размещение сетевой арены

Выбран **Render Free + Neon Free PostgreSQL**. В `render.yaml` указан `plan: free`;
платного диска, платной базы Render и других платных ресурсов нет. Код проверен
локально. Публичный сервис пока не создан.

## 1. Бесплатная база Neon

1. Открыть [Neon](https://console.neon.tech), войти и создать проект
   `robo-workshop-arena` на тарифе **Free**. Регион — ближайший к Frankfurt.
2. Оставить минимальный compute и автоматическое засыпание. Не включать платные
   дополнения и не переключаться на платный тариф.
3. Открыть **Connect**, выбрать базу и роль, включить **Connection pooling**.
   Скопировать строку вида
   `postgresql://USER:PASSWORD@HOST-pooler.../neondb?sslmode=require...`.
   Если показана команда `psql '...'`, нужна только строка внутри кавычек.
4. Вставить её непосредственно в Render на следующем шаге. **Не отправлять
   строку базы в чат, GitHub, JSON игры или APK.** Игрокам нужен только HTTPS API.

На 2026-11-15 Free включает 100 CU-hours/месяц и 1 GB на проект, без ограничения
срока и без банковской карты. При исчерпании compute-квоты обслуживание
приостанавливается до следующего расчётного периода. Проверять Usage в Neon.
Источники: [тариф](https://neon.com/pricing),
[подключение](https://neon.com/docs/connect/connect-from-any-app).

## 2. Бесплатный сервер Render

1. После завершения локальной работы отправить актуальный код в свой репозиторий
   `499jdkd/Robo-Workshop-Steel-Arena`. Проверить `git status`: ключи `.signing`,
   `.env`, базы, сохранения, `.venv`, `.cache` и `build` должны оставаться вне Git.
2. Открыть [Render Dashboard](https://dashboard.render.com) → **New → Blueprint**.
   Подключить репозиторий и нужную ветку. Blueprint path: `render.yaml`.
3. Проверить: один Docker Web Service `robo-workshop-arena`, Frankfurt, тариф
   **Free**, без диска и отдельной базы Render. Не выбирать Starter.
4. В **CLICKER_ARENA_DATABASE_URL** вставить приватную строку из Neon. Значение
   `sync: false` означает, что секрет задаётся в панели, а не хранится в Git.
   Сохранить и запустить создание сервиса.
5. Дождаться **Live**, открыть
   `https://<выданное-имя>.onrender.com/health`. Ожидаются `protocol: 1`,
   `rules_version: 3`, `opponents: human-only`, `storage: postgresql`.
   Эта проверка не будит базу.
6. Один раз открыть `/ready`: ожидается `{"ready":true,"storage":"postgresql"}`.
   Этот запрос подключается к базе и создаёт таблицы при первом запуске.
   При 503 проверить переменную Neon, compute и журнал Render.

Обновления сервера запускаются вручную. Render Free засыпает после 15 минут
без входящего трафика; первое обращение после простоя может быть долгим.
Если клиент показал ошибку, дать серверу проснуться и нажать «Повторить».
Не использовать keep-alive-ботов: они расходуют квоты Render и Neon.
Локальные файлы Render Free временные, поэтому сетевые данные хранятся в Neon.
Офлайн-сохранения игры остаются на устройстве.
Для полностью бесплатного варианта не добавлять платёжный метод Render:
при превышении трафика сервис тогда приостанавливается вместо доплаты.
Сборки также расходуют месячную квоту. Если карта уже добавлена для других
проектов, проверить Billing и лимиты расходов до запуска — один `plan: free`
не отменяет возможную плату за превышение трафика.
Источники: [Render Free](https://render.com/docs/free),
[Blueprint](https://render.com/docs/blueprint-spec).

## 3. Подключить игру

Передать разработчику **только публичный HTTPS-адрес Render**, без `/health` или
`/ready`. До пересборки Windows можно проверить из терминала:

```powershell
$env:CLICKER_ARENA_URL = 'https://<выданное-имя>.onrender.com'
uv run python src/main.py
```

Для обычных игроков адрес записывается в `src/assets/config/network.json`:

```json
{ "arena_url": "https://<выданное-имя>.onrender.com" }
```

Затем собирается новая версия Windows и APK. Ввод адреса игроком не требуется.
В тестовых сборках v25 адрес пуст: публичный сервер ещё не существует.
Тренировочные бои с обозначенными ботами работают независимо от него.

## 4. Внешняя проверка перед запуском PvP

- Два независимых клиента через внешнюю сеть: поиск, полный бой, одинаковый
  результат, история и рейтинг. Это ещё предстоит проверить.
- Запрос дружбы принимает только получатель; код дуэли создаёт один матч.
- Прерывание соединения и повтор команды не удваивают награды.
- После **Restart service** в Render сохраняются профили, друзья, кланы и матчи.
  Не удалять Neon-проект и не создавать новую пустую базу вместо прежней.
- Клановые задания и войны проверяются после стабилизации публичного PvP.

## Локальная проверка PostgreSQL

Проверена PostgreSQL **18.7** из официальных Windows binaries EDB: друзья,
кланы/роли, параллельные приглашения, откат ограничений, точность таймеров,
повторные ходы и однократные награды. Два клиента основной игры завершили матч
через настоящий HTTP за 14 ходов. После перезапуска HTTP-процесса сохранились
профили, друзья, история, рейтинг и состояние боя.

```powershell
# Только отдельная локальная тестовая PostgreSQL, не Neon и не боевая база:
$env:CLICKER_TEST_POSTGRES_URL = 'postgresql://postgres@127.0.0.1:5432/robo_workshop_tests'
uv run python -m unittest discover -s tests -p test_postgres_arena.py -v
uv run python tools/smoke_online_server.py --postgres-local
```

Тест создаёт собственную временную схему и отказывается работать с удалёнными БД.
API и модель доверия: [server/README.md](server/README.md).
