# Первая тестовая загрузка в Google Play

Подготовлена отдельная сборка 17, версия 0.1.1, пакет `com.mycompany.clicker`.
Файл для Console: `build/play-test-v17/clicker.aab`.
Результаты проверки: `build/play-test-v17/verification.json`.
Файл AAB загружается в Play Console; на телефон устанавливается версия из Play.

## Что включено в тестовую сборку

Это копия актуальной игры с исправлением наградного видео из APK16. Для
проверок используются Google demo App ID, баннер и наградной блок. В игре
есть явные подписи тестовой рекламы. Обычное тестовое видео позволяет проверить
выдачу игрового бонуса, а диагностическая кнопка видео не выдаёт награду.
Оба вида тестовой рекламы не приносят дохода.

Рабочие ID владельца в основном проекте и ранее собранный APK16 сохранены.
Подготовка происходит в `.cache/play-test-v17`, включая отдельную папку сборки.
`build-input.json` фиксирует хеши исходников и преобразованных файлов.

## Куда загрузить

1. В Play Console создайте приложение для первой загрузки. Название карточки
   задаёт владелец; пакет этой сборки — `com.mycompany.clicker`.
2. Откройте «Тестирование и выпуск → Тестирование → Внутреннее тестирование»
   (Test and release → Testing → Internal testing).
3. Создайте выпуск и настройте Play App Signing. Для нового приложения можно
   поручить Google создать ключ подписи приложения. Наш AAB подписан отдельным
   ключом загрузки, который затем используется для следующих отправок.
4. Загрузите **clicker.aab**, укажите описание изменений и сохраните выпуск.
5. Добавьте тестировщиков и отправьте им ссылку подключения к тесту после
   выполнения обязательных действий, показанных Console.

Внутреннее тестирование удобно для первой проверки и поддерживает до 100
выбранных тестировщиков. Оно не заменяет обязательное закрытое тестирование
нового личного аккаунта: для заявки на production нужны как минимум 12
тестировщиков, непрерывно подключённых к закрытому тесту 14 дней, и последующее
одобрение доступа Google. Этот AAB технически подходит и для закрытого трека,
когда заполнены необходимые настройки приложения.

В аккаунт Console ничего автоматически не загружалось, выпуск не публиковался.
Проверка AAB не является одобрением приложения Google.

## Подпись и существующий прогресс

APK16 подписан сертификатом Android Debug. Новая тестовая линия использует
настоящий ключ загрузки; установочные APK из Google Play подписывает Play App
Signing. Android не установит такую версию поверх APK16 с другой подписью.

Сохраните установленный APK16, пока не сделана копия его прогресса. Роботы,
иконки, корм и инкубатор хранятся на устройстве: прежний сервер рейтинга
не хранит всю коллекцию. Удаление приложения удаляет эти локальные данные.
Для первой проверки используйте другое устройство или эмулятор. Перенос
существующего игрового сохранения следует подготовить до замены APK16 на этом
же телефоне. При сборке и проверках установленная игра не удалялась.

## Ключ загрузки

Закрытые файлы находятся в `C:\Clicker\.signing`; вторая защищённая локальная
копия — `C:\Users\dell\.android\play-upload-backups\clicker`.
Доступ к этим папкам ограничен текущей учётной записью Windows и SYSTEM.
Сохраните всю папку в безопасной внешней резервной копии.

`clicker-upload.jks` и `upload-password.txt` — закрытые файлы. В Play Console
загружается AAB. Публичный `upload-certificate.pem` можно предоставить, если
Console явно запрашивает сертификат загрузки. Пароли в командах и отчётах
не выводятся; существующий ключ при повторной подготовке не перезаписывается.

## Следующие сборки

```cmd
build_google_play.cmd 18
```

По умолчанию это тестовая реклама. Перед обновлением увеличивайте номер;
использованный в Google Play номер повторно загрузить нельзя.
Отдельный номер можно указать непосредственно:

```cmd
.venv\Scripts\python.exe tools\build_google_play.py --build-number 18 --build-version 0.1.2
```

Рабочая реклама переключается только явным параметром после подготовки
монетизации и проверки приложения:

```cmd
.venv\Scripts\python.exe tools\build_google_play.py --build-number 19 --build-version 0.1.2 --ads-mode live
```

Этот режим берёт рабочие ID из основного проекта. Основные исходники при
выборе режима не переписываются.

## Перед закрытым тестом и публичным выпуском

В Console потребуется проверить карточку, «Есть реклама», возрастной рейтинг,
целевую аудиторию, политику конфиденциальности и сведения Data safety. Игра
передаёт статистику и ID игрока серверу, а рекламный SDK требует собственных
раскрытий. Поэтому форму о данных следует заполнять по фактическому поведению
игры и документации SDK.

Для заявленной смешанной аудитории нужно отдельно закончить проверку Families,
нейтрального определения возраста и допустимой версии рекламного SDK. Текущая
игра использует строгие детские настройки, рейтинг G и неперсонализированные
запросы; это не является подтверждением прохождения Families review.

Для рабочей рекламы понадобятся опубликованная страница поддерживаемого
магазина, привязка в AdMob, app-ads.txt и проверка готовности. Внутренний тест
сам по себе не подтверждает готовность настоящих рекламных показов.

Журнал первого AAB содержит предупреждение о небольшом исходнике значка
305×273. Для оформления публичного релиза следует подготовить квадратный
значок нужного разрешения. Это не блокирует техническую проверку AAB.
